## Preservation and cleanup

The capture fixture snapshots and restores these eleven preference groups:
`appearance`, `accessibility`, `weather`, `keyguard`, `setup`, `leo-home-canvas`,
`settings-ui`, `clock`, `browser`, `files-ui` and `gallery`. It verifies the restored
maps against the originals. A separate host comparison of pre/post XML maps also
confirmed all eleven groups match, including browser history/resume state.

UI automation uses `FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES`. The wake lock is
bounded and released, the loopback server is closed, and the UUID fixture is
removed. Only the temporary test APK and owned capture staging files are cleaned
up. Screenshots are reviewed for personal data before entering Git.

There are no calls, messages, recordings, radio toggles, SIM-role changes or
firmware writes in the capture procedure. The latest saved battery session is
marked interrupted/invalid, with zero recorded elapsed/awake durations. It does
not provide an endurance result; a completed hardware measurement remains open.

## Inventory and checks

The old inventory parser expected a retired launcher dispatcher. It now reads
the explicit `AppCatalog.Entry` registry, checks contiguous unique IDs and known
syntax, preserves route extras, validates targets against the manifest, and checks
that Home still delegates to that registry. Unknown formats fail closed.

- **48 catalog destinations**, **14 contextual/Settings-only**, **34 full-launcher
  entries**. These counts describe source wiring, not independent hardware tests.
- **110 declared activities**, **one activity alias**, **two providers**,
  **12 receivers** and **12 services** with source implementations.
- **96 host tests passed**, including seven inventory parser/boundary tests.
- The installed shell's earlier **700 Home/standby checks**, **188 daily UI checks**
  and hardware-key results remain tied to the same APK hash; they were not
  reclassified as new feature tests by this documentation session.

## Reproducing the capture fixture

Use the prepared Windows SDK/JDK environment in [REBUILD](REBUILD.md). The class
JAR must correspond to the shell installed on the explicit development handset.
Building the fixture does not install it or change firmware.

```powershell
python -X utf8 android81/audit-leo-shell.py
python -m unittest discover -s android81/tests
python android81/build-pocket-tests-windows.py --showcase
```

On the idle reference handset, after explicitly installing the owned test APK:

```powershell
python android81/framework-command.py --timeout 180 /system/bin/am instrument -w ro.leo.visual.showcasechecks/ro.leo.visual.ShowcaseCapture
```

The successful run reports `CAPTURED 23 documentation scenes; local fixtures only`.
The global-menu screenshot is captured separately using physical scan codes.
The fixture handles an already-running single-task Home with a bounded activity
monitor, waits for the local browser document and painted body, and closes the
separate WebView activity before restoring browser state.

Capture logs, preference backups and development previews remain in ignored
`output/showcase-2026-11-23/`; they are not published with the gallery.
